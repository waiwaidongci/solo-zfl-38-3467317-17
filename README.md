# 古船模型帆索校准（含桅杆损伤检测与寿命放行）

运行：

```bash
npm start
```

访问：

- 帆索校准工作台（旧入口，保持可用）：`http://localhost:3038/`
- 桅杆损伤检测与寿命放行：`http://localhost:3038/masts`

数据保存在 `data/model-rigging-calibration.json`（tmp + rename 原子写，重启后数据仍在）。

## 桅杆损伤与寿命放行

- **登记**：材料、截面形式（圆管/实心圆杆/矩形杆/绳缆）、公称尺寸（自动算公称面积）、许用应力、基准声速、检测点，可关联旧工作台的模型。
- **检测录入**：每条检测提交本次新增的裂纹（深×长）、腐蚀（深×宽）、断丝数、声速、载荷与载荷循环。
- **评估**：
  - 剩余截面损失 = 累计裂纹/腐蚀等效面积 + 绳缆断丝占比；
  - 应力比随剩余截面放大；
  - 累计疲劳按 Miner 法则和 S-N 曲线（N = N₀·(σ_ref/σ)^m）累加；
  - 声速衰减 = 1 − 本次声速/基准声速。
- **安全等级**：任一指标达到**监测线**（截面 5%、应力比 0.7、疲劳 0.3、声速 5%）纳入持续跟踪；达到**停用线**（截面 15%、应力比 1.0、疲劳 0.8、声速 12%）**立即冻结校准与交付**，页面显示阻断原因。
- **修复/复检**：冻结时服务端把修复单**绑定到实际触发冻结的检测记录**（`frozenByInspection`），复核人必须与该记录的操作者不同（否则 403）；请求体自报的“原检测人”会被忽略，无法冒名；复检未过不得解冻；复检通过以复检数据为新基线（旧损伤标记核销），指标仍达停用线则继续冻结并把触发记录改绑本次复检。
- **放行**：无冻结/停用/待复核修复单方可放行；放行只能成功一次；放行后再录入检测，旧放行结论失效，须重新放行。
- **旧工作台联动**：关联桅杆冻结期间，状态进入校准中/待复核/已交付、新增帆索任务均返回 423，卡片显示冻结横幅。
- **并发与一致性**：写队列串行化；检测/修复/复检/放行**必须携带 `expectedVersion`**（缺失返 428，过期返 409），并发请求不可能同时成功；放行只能成功一次。
- **幂等键作用域**：`Idempotency-Key`（或 body 字段）同时绑定 操作+资源路径 与请求内容指纹（剔除版本/幂等字段后的 SHA-256）；三者完全一致的重试直接回放同一响应（不重复落盘，响应头带 `X-Idempotent-Replay: true`）；同一把键用于别的资源、别的操作或不同请求体时返 409 `idempotency_key_reuse_conflict`，绝不回放旧响应。**重放返回的 `X-Version` 始终是当前已提交版本**（即使首次提交后状态已被其他写入推进），客户端按该版本继续检测/修复/放行不会被过期版本挡回。
- **回滚**：写盘失败或事务中任何校验失败（403/409/422/423/428）都不推进版本号，损伤、寿命与冻结状态整体回到上一已提交版本。
